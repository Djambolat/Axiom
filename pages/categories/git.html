Пояснение с самого нуля

Всем салам алейкум, это гайд по понятию что такое GitHub, Git, ветки,pull request, merge, commit со студенческого взгляда.
представьте следующее: Вы с друзьями( допустим вас 5 человек) собрались для того что бы сделать сайт-маркетплейс(что то вроде Wildberries).
Вы умеете писать код, кто то из вас берет на себя систему продавцов, кто то товаров, а кто то лучше разбирается в создании системы авторизации, однако возникает проблема- вы не умеете работать в команде.
Представьте до чего ужасно работать целой командой за одним компьютером. Это крайне не эффективно и неудобно. Гораздо лучше работать каждому за своим ПК. так вы и делаете: каждый приобретает себе компьютер.
Но возникает еще одна проблема. файлы разработки(допустим у нас только 2 файла- index.html и styles.css) находятся на пк тимлида(Лидер команды) .И он передает вам архивированный файл с кодами по почте.
Важно понимать что работая в команде, далеко не всегда каждый работает над своим не зависимым файлом, иногда один и тот же файл редактируется несколькими программистами.
Это значит что условный файл index.html будет редактироваться несколькими вашими товарищами(к примеру 4 человека).
И вот у нас сложилась следующая картина: тим лид создал у себя на пк 2 пустых файла(index.html и styles.css) он их упаковал в один архив и отправил вам всем по почте. 1 человек делает стили в файле .css, а 4 других добавляют свои функции в файл .html.
Когда вы закончили, каждый из вас отправляет вами отредактированные файлы обратно тимлиду по почте.
Какая картина перед тимлидом? он видет перед собой один файл .css и 4 разные версии файла .html(то есть ему на почту пришел 1 файл .css и 4 разных по содержанию но одинаковых по названию файла .html). вставить код новопришедшего файла .css в пустой оригинал не составит труда, а вот с .html дела иначе. тимлид должен взять с каждой версии только те отрывки кода которые выполняют конкретную функции и вставить их в пустой оригинал да еще и так что бы весь этот конструктивно собранный код слаженно работал. Это целое дело, которое очень сильно тормозит разработку.
Именно для этого существуют Git и GitHub. GitHub это онлайн сервер куда тимлид может закинуть оригинал проекта, кстати, пространство в GitHub где находятся все файлы проекта называется репозиторием. А остальная команда получив ссылку на репозиторий может видеть его содержимое (файлы проекта).
После того как тимлид загрузил проект в репозиторий GitHub, каждый участник команды больше не просит архивы по почте, ведь помимо того что команда видит то что в репозитории, каждый может загрузить копию на свой пк. И здесь нам впервый раз пригодиться Git.

Git и GitHub

Git — это система контроля версий, которая позволяет отслеживать изменения в коде и работать над проектами совместно с другими разработчиками. GitHub — это веб-сервис для хостинга проектов, использующих систему контроля версий Git.

Основные команды Git:

git init — создает новый пустой репозиторий в текущей папке.

git clone — копирует существующий репозиторий с сервера на компьютер.

git status — показывает состояние файлов: изменены, удалены или готовы к сохранению.

git add — добавляет изменения в зону ожидания перед сохранением.

git commit — сохраняет добавленные изменения и создает точку восстановления.

git branch — управляет ветками кода, показывает их список или создает новую.

git checkout — переключает между ветками или возвращает старые версии файлов.

git merge — объединяет изменения из одной ветки в другую.

git remote — управляет связью между вашим компьютером и сервером (GitHub/GitLab).

git push — отправляет ваши сохраненные изменения на удаленный сервер.

git pull — скачивает свежие изменения с сервера и сразу объединяет их с вашим кодом.

git log — выводит историю всех сделанных сохранений (коммитов).

git restore — отменяет изменения в файлах, возвращая их к последнему сохраненному состоянию.

git fetch — скачивает данные с сервера, но не объединяет их с вашим кодом автоматически.

git diff — показывает разницу между текущим кодом и прошлым сохранением.

git rm — удаляет файлы из проекта и перестает следить за их изменениями.

git mv — перемещает или переименовывает файлы проекта с сохранением истории.

git stash — временно прячет незавершенные изменения, чтобы очистить рабочую зону.

git pop — возвращает обратно ранее спрятанные командой stash изменения.

git reset — сбрасывает изменения, возвращая проект к указанному коммиту (может удалять код).

git revert — создает новый коммит, который отменяет действия любого старого коммита.

git rebase — переносит ваши коммиты поверх изменений из другой ветки для чистой истории.

git tag — ставит метку на важный коммит, например, обозначает версию программы (v1.0).

git config — настраивает параметры гита, такие как имя автора и электронная почта.

git show — показывает подробную информацию и изменения конкретного коммита.

git cherry-pick — копирует один выбранный коммит из любой ветки в вашу текущую ветку.

git reflog — показывает полную историю вообще всех ваших действий для спасения удаленного кода.

git -v — выводит текущую версию установленной программы Git.
